# Local eye-contact camera

The native app starts a separate local worker: DirectShow input → MediaPipe face/iris landmarks → calibrated FLX eye crops on DirectML → feathered eye-only compositing → OBS Virtual Camera. The worker uses RGB for the trained network and detector, with BGR conversion for OpenCV compositing. It keeps one latest capture frame rather than accumulating video latency. Camera frames and calibration remain in memory; optional JPEG previews travel only through the local app event channel.

Choose a named input camera and the RX 9070 XT, start preview, calibrate while looking at the camera, then calibrate while reading notes just below it. Hold each gaze for about two seconds. Maximum vertical correction defaults to 12° and is capped at 15°; horizontal correction is capped at ±3°. Closed eyes, missing faces, clipped crops, large head turns and gaze outside the calibrated range pass through. The checkbox and zero strength allow direct comparison with original video. Stop closes input/output and clears calibration and preview. OBS Virtual Camera is excluded from input selection to prevent feedback.

Seven core tests verify unchanged pixels outside the eye mask, blink passthrough, calibration ordering/stability, bounded angles, clipped-crop rejection, zero/lost-face passthrough and RGB order. Five browser tests cover the UI and meeting/context workflows. The native acceptance run (`node scripts/camera-native.mjs`) verifies real named DirectShow devices, the RX adapter, feedback rejection, preview delivery, an independent 1280 × 720 OBS consumer, and Stop cleanup. Numeric results are in `artifacts/camera-native/results.json`; its layout image deliberately hides the camera preview.

On this machine, input index 0 is Camo and output index 1 is OBS Virtual Camera. Camo currently has no detectable face and intermittently supplies about 1 fps. The app reports the low input rate. A separate standalone run obtained 30 fps and about 5–6 ms from captured-frame receipt to virtual output without a detected face. This excludes delay inside Camo, OBS consumers and meeting software. Neither run proves calibrated eye correction, naturalness, stability on a real person, or complete call latency. Those checks require a connected phone/webcam, a visible face and the two calibration steps.

The production worker is frozen with Python and native dependencies; users do not need TensorFlow or a Python installation. OBS's virtual-camera driver must already be installed. The driver was present on this machine and actual output passed. Numeric FLX model parity and actual DirectML kernel evidence are documented in [gaze-models.md](gaze-models.md).
