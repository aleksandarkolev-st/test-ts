## Implemented behavior

| Decision requirement | Implementation and verification |
| --- | --- |
| Local transcript revisions; finalization distinct from acceptance | `QuestionDetector` uses separate activity, revision, final and confirmation state. The normal controller freezes accepted frames rather than remotely steering each revision. Generic short/long acoustic waits are evaluated with semantic reply intent in the answering call. This does **not** certify a learned semantic-completeness detector; real multipart splits remain a possible failure. |
| Current request independent of obsolete echo | Immutable generation/context/input identities; one current job, one retirement allowance and latest coalesced pending intent. Dispatch never waits for an obsolete `userMessage` echo. Exact old-output gates and final-frame eligibility have regression coverage. |
| Bounded cancellation, capacity and recovery | Codex acknowledgement/connection retirement and capacity recovery have explicit deadlines and fixture faults. HTTP unknown remote termination holds local capacity for 1,500 ms; unavailable capacity fails after 2,500 ms. Local bounds do not prove provider-side termination. |
| Full recognized session and original code | RAM ledger retains both source channels, all recognition revisions, accepted requests, exact generated sources and timestamped viewport ranges. Cancellation changes computation, not originals. Completed/interrupted exact code is retrieved by literal source identifiers without reconstruction, with generation provenance. |
| Seen prefix when interrupted | Renderer acknowledgement after paint, clipping/scroll geometry and UTF-16/UTF-8 boundary conversion. Generated tails and later paint ranges cannot enter a snapshot pinned to an earlier speech start. Delayed acknowledgements retain retired history without authorizing the active panel. |
| Derived summaries and bounded working context | Original ledger is independent of summary success/failure. Complete source views are used within the context budget; whole-item literal retrieval and recent exchange priority apply beyond it. Completeness of the archive is not a guarantee of retrieval or model recall. |
| Privacy | Production memory clears at Stop; no transcript/answer disk storage added. Native collectors explicitly write authorized synthetic validation artifacts into ignored directories. Microphones are disabled in playback trials; two-source separation also has fixture coverage. Labels identify remote/self channels, not verified per-person diarization. |
| No repeated history inside retained backend state | Prepared ephemeral Codex threads receive one authoritative snapshot each while the authenticated process stays warm. HTTP requests supply history once, `store:false`, `stream:true`; no unsupported continuation or billed API fallback is added. |
| Reader and consumer isolation | Bounded lossless per-request mailbox; acknowledgements/cancellation/terminal events bypass slow output delivery. Overflow and display-size limits fail explicitly. Fixtures stall consumers and retain ordered deltas. |
| Brief and detailed objectives | Explicit UI objective and version-bound Expand. Requested complete code and proof are preserved. Detailed work attaches to its parent generation; it does not replace newer focus. No second model runs by default. All acceptance comparisons keep GPT‑6.1-Sol on low effort, as instructed. |
| Backend comparison | Codex is validated first; public direct ChatGPT-plan HTTP runs use the same controller, model, effort and replay inputs. Unsupported capabilities are recorded. A Codex-only fault command does not certify HTTP forced reconnection. |
