## Questions and capture

Native audio tests play unchanged, hashed mono PCM waveforms through **T24E390**. The app captures that output through its normal loopback path; local Nemotron transcribes it with 160 ms chunks. Typed tests invoke the native Ask control and explicitly exclude audio, transcription and automatic endpoint delay. The microphones are disabled in these synthetic recordings, rather than recording nearby people. Production continues to recognize both output and microphone sources.

These are simulated meetings and technical interviews with an authenticated assistant, not human interview certification. Saved questions include CUDA collective proofs, numerical reasoning, directed graphs with negative cycles, transactional invariants, changed constraints, and underspecified challenges. No expected answer or fixture identity selects production routing, acceptance, model, context retrieval or response policy.

All measured assistant runs use **`gpt-6.1-sol`, `low`**. The final contextual/backend/history/objective cells use standard tier (`null`); the original baseline/controller cells retain their source manifest's identical tier. The model catalog establishes availability, while recorded provider events establish actual inference; a failed startup does not prove inference capability or answer latency. Codex also validates the catalog's supported effort values. Unsupported direct-plan capabilities fail visibly; there is no billed API fallback.

## Measurements and reasoning checks

`measure-controller-validation.mjs` requires an exact journal hash in its review file. Every row remains in correctness/completion/missing/error counts. Only a reviewed correct substantive claim actually painted in the viewport supplies useful-feedback latency. First words, input acknowledgements and ungraded openings are separate measurements. Missing or incorrect useful delivery ranks after finite correct delivery in the all-row p95, without assigning a fabricated timeout latency.

Codex actual submission is its instrumented flushed transport write. HTTP request-send timing does not prove a wire write; that field remains unknown. Capture uses physical device-position crossing bounds for the last nonzero source sample, host/native clock anchors, per-generation timings and actual overlay paint samples. Recognized question text can differ even with identical audio. Lexical WER is reported without silently repairing identifiers or normalizing numerals; source accuracy and accuracy conditional on recognition are separate judgments.

Native baseline/control captures check the frozen executable hash against its preserved build manifest and record source Git-blob hashes at that manifest's declared commit. Observed current checkout hashes are separately labeled: later edits must not be presented as the source of an older frozen executable. Renderer hashes remain independent, including the shared current renderer used with the c704a75 native baseline. Build provenance is not a reproducible-build attestation.

Reasoning review checks assumptions, causal arguments, counterexample executions, changed constraints, exact identifiers, synchronization contracts, arithmetic and completeness. It does not demand hidden chain-of-thought. Code and proof are assessed independently:

- `compile-controller-answer-cuda.mjs` uses the pinned real NVIDIA nvcc/MSVC toolchain from the existing compiler manifest to compile unchanged fenced CUDA/C++ sources. Failed snippets remain failures. Compilation does not prove GPU execution.
- `check-controller-answer-code.mjs` compiles/runs exact C++ code with explicit contracts. For nineteen-lane reductions, a documented CPU intrinsic shim and mechanical PTX lane-id substitution exercise the recorded algorithm's basis-vector coverage, all-caller results, matching collectives, participating sources and six-shuffle limit. This is CPU emulation, not NVIDIA hardware certification.
- Integer-branch checks bind original and corrected operators separately and execute 2,003 inputs per exact source. Log-recovery checks link the CRC-32C dependency explicitly requested by the question, compile the unchanged C++20 CLI, and supply independent valid/truncated/corrupted/sequence-gap/maximum-length byte files. No recovery algorithm is repaired.
- `check-controller-answer-python.py` evaluates unchanged required entry points against independent path/cycle enumeration, exhaustive small graphs, seeded multigraph/extreme-weight probes, and high-precision Decimal numerical oracles. These finite checks supplement the invariant and complexity proof review; they do not prove every allowed input.
- Exact-length walks use a separate forward dynamic-programming oracle, 6,448 small/large-length contracts, full small-witness continuity/cost checks and sampled indices at length 10^18. Predictable monitors use independent integer-product arithmetic and fully consume finite inputs, including invalid values after threshold crossing. Pipeline schedules are checked against resource, host/device ownership and timing inequalities plus an independent lower bound. Oracle regressions include deliberately invalid implementations; passing finite checks does not replace a proof.
- `check-controller-answer-sql.mjs` executes unchanged recorded SQL in an owned local PostgreSQL test instance. It schedules BEGIN/body/COMMIT separately to force two overlapping transactions, preserving surrounding comments and procedural bodies, checks serialization failures and a full retry, and shuts down only its own database. A separate control explicitly changes the actual isolation clause to repeatable read without rewriting comment text; that control is not scored as unchanged model source. Results bind the grader/parser source hashes. These synthetic database artifacts are separate from production meeting persistence. Run compilation/execution checks after capture or during documented scheduled quiet intervals, never during measured audio/inference.

The collector does not repair answers after generation. Reviewer verdicts, executable results and latency evidence are source-bound and remain separately labeled. Model-assisted review, if used, is not independent expert certification.

For exact-function questions that do not require a code fence, an execution spec may explicitly set `allowUnfencedExactSource:true` on its `integer-branch` contract. Selection then requires one standalone occurrence of the exact externally supplied source, byte for byte, and records that extraction mode. It does not normalize indentation, operators, names or newlines; quoted prose and duplicate candidates are rejected. An actual selected code fence keeps its original contents even if wrong. Complete-program contracts and questions requiring a fence keep their existing fence requirement. Grader regressions include wrong-operator and misleading-prose cases. Run those regressions and compiler checks after every capture queue, preserve grader/parser hashes, and distinguish a grading-format issue from an absent or incorrect model implementation.

`controller-reconnection-reasoning-probes.json` supplements the earlier ambiguous CAS/reconnection question. It explicitly names assistant transport, asks for the actual prior thread roles/values and byte-exact original code, then requires the invariant and a counterexample after changing the loop. Compare exact code against each backend's actual initial answer, never a prewritten solution. The existing native fault hook actually closes Codex only; Plan rows disclose that HTTP was not forcibly disconnected. Keep the earlier ambiguous trial and its strict missing-explanation verdict, without treating that wording failure as a mathematical CAS error or proof of lost memory. Run this supplement after the primary capture queue and before any executable grading.

`prepare-controller-backend-controls.mjs JOURNAL REVIEW ORIGINAL_MANIFEST NEW_OUTPUT_DIRECTORY` derives identical backend inputs from actual accepted source contexts. It verifies journal/review/manifest/waveform hashes, carries the recorded objective/tier, includes incorrect reference outcomes, and discloses requests for which no accepted context exists. Exact-text replay uses actual recognized text; native replay keeps the original waveform and allows measured recognition differences. Neither mode recomputes context from each backend's new answers. The preparation tool is validation-only and has no production topic or intent policy.

`nemotron-finalization-replay.mjs JOURNAL NEW_OUTPUT VULKAN_DEVICE` tests the installed local runtime's documented commit protocol against automatic endpointing using source-bound short-utterance waveforms, preceding audio timing and controlled PCM chunk phases. It preserves 160 ms chunks, weights, device and endpoint settings, reverses trial order, and checks a later turn on the same socket. Every cell owns a fresh authenticated loopback service, awaits its exit, and closes message collection before the next cell. This prevents the closing-socket callback overlap that invalidated the first collector. That stopped experiment remains an invalid experiment, with operator-induced shutdown distinguished from an independent service failure.

Record the primary observation window's actual duration and keep finals without verified source-time binding unattributed: receiving a prior question's delayed final after target speech does not supply target WER or recovery credit. A separate post-window commit drains both variants, with a bounded acknowledgement wait; its latency is not the primary endpoint result. A following-turn probe then uses that socket, with a bounded observation window. Empty text in that window does not prove that the connection is dead. Preserve all eight cells and protocol failures. The collector writes opt-in synthetic artifacts only. Direct PCM excludes WASAPI/resampling and assistant output load; it does not establish the original native failure cause or authorize predicted words. Run it after native captures and before other heavy grading. No production commit policy is promoted from protocol documentation alone.

Disclosed observer interference is attached to the source-bound row review. Measurements retain that row in all correctness, completion, missing-answer and overall latency results, report its interference flag, and provide a separate `nonFaultNonObserverAcceptedToWriteMs` distribution excluding requested fault probes and known observer interference. ## Promotion gates

The acceptance goal is reliability during long, difficult coding interviews. A fast opening or a correct isolated explanation does not satisfy it. Assess each requested implementation, proof, changed assumption and exact-source reference against its actual recorded contract, and track whether interrupted parent work is eventually delivered. Preserve missing speech, wrong interfaces, unsupported reasoning and incomplete code as failures even when a later answer is correct. Report performance over the full elapsed workload and the required follow-up/recall cohorts separately; finite synthetic tests and successful compilation do not establish high-stakes readiness. No expected solution enters production prompts or request routing.

Repeat the frozen `history-0/10/30/60` controls on the current verified binary and both backends. Their recorded source transcript prefixes, current question/context and original Why waveform stay identical; every cell starts a fresh app. Use two repetitions, reverse history-size order in repetition two, and reverse backend order. These source histories change submitted context size without imposing elapsed app age. Record recognition differences, missing replies and incomplete causal explanations rather than using a typed success to repair the audio result.

Compare the elapsed hour's final fixed-context request with a separate fresh-app control using that exact question, context, objective, model and effort. Complete two identical warm-up requests before the fresh measured request; preserve their startup outcomes separately. Inspect actual warm/prepared-thread provenance when available. A cold first request is not a healthy warm control, and HTTP actual wire-write/reconnection is not certified by pool reuse alone. These sequential observations still permit provider and operating-system drift, so do not call one pair a causal aging or leak result. Run these controls after long/reconnection captures and before compilation or model grading.

Accepted HTTP replies use the same strict intent/text schema as Codex. Verify the actual outgoing `text.format` JSON-schema body in fixture tests, including answer-only explicit acceptance and unchanged free-form summary calls. Fixture compliance does not establish support by the signed-in Plan route: require nonempty authenticated inference without framing errors before dependent hours-long runs. Preserve failed envelopes as visible failures; do not infer uncaptured provider bytes or silently retry through a billed API. Compare the old failed reasoning trial with the same new questions, while disclosing that natural generated history differs. Run Codex first on the changed build with model/effort unchanged.

The proposed targets remain acceptance criteria: healthy warm accepted-to-write p95 below 250 ms, ordinary follow-up useful feedback p50 at most 2 seconds/p95 at most 3 seconds, no silent lost final request, no obsolete active-panel text, no material correctness/completion regression, and no material age degradation under matched workload. Complex proofs have separate completion measurements. A successful fixture or one fast sample cannot establish these gates.

The final findings and recommendation must be based on completed authenticated captures and their audits. This protocol is not a latency-success claim or a substitute for implementation.

For a saved waveform that creates several generations, preserve the original collector row and audit every generation separately. `controller-source-generations.mjs` compares recorded utterance floors with the playback/host-native clock envelope; it does not select the last successful answer or silently discard a cancelled final request. Missing clocks and boundary overlap remain ambiguous. This is an offline timing association, not proof of acoustic provenance: the native ASR client uses its sent-audio frontier, and an observed opening floor can precede the recorded playback launch. Manual source/event review remains necessary. Bind useful paint, actual submission and completion to the selected generation before computing any corrected measurement; never combine an opening's completion with the full request's proof.

The recorded multipart-focus regression includes a completed opening, a full proof request superseded during output, and a later ignored input. Its seven tooling tests preserve all outcomes, including the actual ignore event occurring after cancellation and unknown clocks remaining unknown. They verify evidence attribution only. Production must additionally verify that an automatic input rejected by the model cannot destroy legitimate foreground work, while explicit requests and model-accepted follow-ups can take focus promptly. Test this with arbitrary text and intent/frame metadata, without lexical exceptions. Preserve original acceptance-to-write clocks if a later semantic-focus transition is introduced; renaming that transition must not manufacture a faster submission result. Keep the frozen running build and collector unchanged through the paired capture queues.
