# Local eye-contact camera

The native app starts a separate local worker: DirectShow input → MediaPipe face/iris landmarks → calibrated FLX eye crops on DirectML → feathered eye-only compositing → OBS Virtual Camera. The worker uses RGB for the trained network and detector, with BGR conversion for OpenCV compositing. It keeps one latest capture frame rather than accumulating video latency. Camera frames and calibration remain in memory; optional JPEG previews travel only through the local app event channel.

Choose a named input camera and the RX 9070 XT, start preview, calibrate while looking at the camera, then calibrate while reading notes just below it. Hold each gaze for about two seconds. Maximum vertical correction defaults to 12° and is capped at 15°; horizontal correction is capped at ±3°. Closed eyes, missing faces, clipped crops, large head turns and gaze outside the calibrated range pass through. The checkbox and zero strength allow direct comparison with original video. Stop closes input/output and clears calibration and preview. OBS Virtual Camera is excluded from input selection to prevent feedback.

Nine core tests verify unchanged pixels outside the eye mask, blink passthrough, calibration ordering and rejection of missing/closed/sparse/moving eyes, bounded angles, clipped-crop rejection, zero/lost-face passthrough, RGB order and the original FLX corner-centered crop geometry. Five browser tests cover the UI and meeting/context workflows. The native acceptance run (`node scripts/camera-native.mjs`) verifies real named DirectShow devices, the RX adapter, feedback rejection, preview delivery, an independent 1280 × 720 OBS consumer, and Stop cleanup. Numeric results are in `artifacts/camera-native/results.json`; its layout image deliberately hides the camera preview.

`scripts/gaze-reference-smoke.py` also exercised 478 actual MediaPipe landmarks and both real DirectML eye models on Google's public sample portrait at 1280 × 720. Across 35 frames, pixels outside the eye crops remained byte-exact and forced blink signals immediately bypassed correction. Warm median landmark/correction time was 8.18/2.70 ms, combined 10.87 ms (p95 11.82 ms), excluding capture/output and validation assertions. Calibration in this probe is deliberately artificial to exercise a 12° model input; it does not establish naturalness, true gaze angle estimation or real-person calibration. Report: `artifacts/gaze/face-integration.json`. Independent full-resolution detections also verify that +12° moves the iris upward, −12° downward, and ±3° horizontal inputs move it in the expected direction. This verifies direction on one public portrait, not correction magnitude in true degrees. The crop now uses the midpoint of the eye corners, matching the original FLX system rather than the average of lid points. The sample image remains outside the distribution.

On this machine, input index 0 is Camo and output index 1 is OBS Virtual Camera. Camo still has no detectable face; earlier runs intermittently supplied about 1 fps, while the latest production poll supplied 30 fps. The app reports the low input rate. A separate standalone run obtained 30 fps and about 5–6 ms from captured-frame receipt to virtual output without a detected face. This excludes delay inside Camo, OBS consumers and meeting software. Neither run proves calibrated eye correction, naturalness, stability on a real person, or complete call latency. Those checks require a connected phone/webcam, a visible face and the two calibration steps.

The production worker is frozen with Python and native dependencies; users do not need TensorFlow or a Python installation. OBS's virtual-camera driver must already be installed. The driver was present on this machine and actual output passed. Numeric FLX model parity and actual DirectML kernel evidence are documented in [gaze-models.md](gaze-models.md).

`COPILOT_CRASH_TEST=1` in the native harness starts the actual Nemotron process and source camera worker, confirms camera preview, then forcibly terminates its isolated parent app. The Nemotron child and both Python launcher/worker processes all exited, leaving zero owned sidecars. Evidence: `artifacts/native-sidecar-crash/results.json`. This verifies unexpected parent-exit containment in the native source build; frozen production startup and normal camera Stop are separately verified by the package check.

The release-specific `scripts/frozen-camera-lifetime.mjs` also verified the actual frozen 0.2.1 worker: a fresh WebView profile opened without a visible state-initialization error, Camo preview arrived on RX 9070 XT, and forced parent termination left zero owned `gaze-worker.exe` processes. The checker distinguishes an early API call before native initialization from a frontend startup failure, and cleanup validates process creation time as well as PID/name. The initial early-API failure is retained separately. Report: `artifacts/gaze/frozen-lifetime.json`. Video had no detected face and the initial input rate was below 1 fps; this check establishes lifetime containment, not calibrated correction or naturalness.

A timed public-portrait replay also ran for 600.004 seconds while the same Nemotron/Vulkan process maintained both actual WASAPI streams. It corrected 17,999 frames at 29.998 fps; median MediaPipe plus FLX/blend processing was 9.66 ms and p95 10.63 ms. Every frame passed full pixel preservation outside both eye crops and forced-blink bypass. Ten varied synthetic speech questions completed during that window, with speech-end-to-first local-fixture token from 611 to 781 ms. Reports: `artifacts/gaze/concurrent-face.json`, `concurrent-run.json` and `concurrent-summary.json`. This establishes these controlled workloads coexisting on RX 9070 XT; the portrait has artificial calibration and no capture/OBS/call transport, so it does not establish live naturalness or complete call latency. Reproduce the face workload with `scripts/gaze-reference-smoke.py --image .local/gaze-reference-person.png --device 1 --duration 600 --fps 30 --report-name concurrent-face` while the documented speech soak runs.

A separate 20.07-second Camo input diagnostic sampled 170 frames at 1280 × 720. MediaPipe reported zero faces/usable eye observations at all three tested confidence settings (0.3, 0.5 and the production 0.6). The diagnostic retained numeric counts only. Report: `artifacts/gaze/camera-detection.json`. The Camo Studio process is running; its connection screen could not be inspected because the Windows UI connector native pipe was unavailable after retry/reset. These observations do not identify the exact connection or visibility problem; live input/calibration still need to be resolved.
