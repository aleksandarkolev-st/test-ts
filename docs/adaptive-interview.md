# Adaptive interview evaluation

The required outcome is a correct, useful phrase at the end of a question or within about 200–400 ms, with p95 below 800 ms, followed by continuous explanations. Passing fixture tests does not establish that outcome. The live runs so far have not met it.

## Signed-in Codex only

The answer and examiner defaults are `gpt-6-luna`. Answers use low reasoning and Fast speed; the examiner uses high reasoning and Fast speed. No API key is needed. Model selection remains configurable, and an existing valid app selection is preserved. Select Luna explicitly when changing an existing installation.

A read-only signed-in catalog check on October 8, 2026 advertised Luna efforts `low`, `medium`, `high`, `xhigh`, and `max`; it did not advertise `none` or `minimal`. The advertised Fast service-tier id was `priority`. The client accepts the UI's Fast alias only if thread creation acknowledges `priority` or `fast`. The catalog evidence is saved in `artifacts/live-service/luna-codex-capabilities-2026-10-08.json`. One initial discovery attempt failed and the read-only retry succeeded.

```powershell
cargo build --manifest-path src-tauri/Cargo.toml --example adaptive-interview
$env:COPILOT_INTERVIEW_OUTPUT='artifacts/adaptive-interview/my-luna-run'
node scripts/adaptive-interview-suite.mjs
```

The suite runs serially to avoid competing inference distorting latency. Each scenario starts an isolated signed-in Codex app-server and performs a real inference warmup before measurement. Warmup duration is saved separately. Only completed successful turns can return their ephemeral thread to the bounded reuse pool; cancellation interrupts the actual server turn before releasing its slot. Stop closes the owned server.

## Scenarios and follow-ups

[The GPU fixture](../tests/fixtures/gpu-interview-suite.json) defines 24 scenarios with 12 adaptive rounds each. These include undefined changes such as “a GPU suddenly becomes x,” performance regressions, apparent memory changes, device loss, rare wrong results, contradictory utilization, partition changes, peer communication, barriers, stale graph replay, numerical changes, stream starvation, irregular input shapes, checkpoint failures, reductions, host/device ordering, and heterogeneous failover.

The fixture supplies a starting question, private evidence, and assessment criteria. It supplies no scripted sequence of expected answers. The examiner sees the actual answer and chooses its next question accordingly: reveal missing evidence, challenge an assumption, request code or a proof, change constraints, or drill into a prior claim. Only actual interview questions and prior answers reach the answer model. Private evidence, assessment criteria, and source references remain with the examiner. Production prompting and routing contain no CUDA answer templates or scenario-specific responses.

The automatic response path asks Codex to classify reply intent in the same inference call that generates the answer. It recognizes implied requests and ambiguous challenges from context. The native output schema constrains the reply to an `intent` and a `text` field; an incremental JSON decoder displays only the decoded answer, preserving exact code and incomplete Unicode escapes. Stable transcript updates are coalesced without a word or topic allowlist. The signed-in scheduler keeps new utterances separate and passes context to the model instead of merging them using English continuation phrases. A newer confirmed useful Codex reply can become visible while an older answer is still streaming.

An acknowledged steer is not necessarily consumed immediately. If a confirmed refinement remains queued for 400 ms while obsolete answer text is streaming, the driver interrupts that attempt, waits for its terminal event, retires its thread, and retries once on another prepared thread. It retains the latest selected excerpts and original attachments, resets the response version, and refuses the retry when terminal cleanup cannot be verified. It does not restart fresh follow-up turns on that timer. Timing distinguishes acknowledgement from consumption and records the restart count. Recognition-error interpretation also happens in the answer inference; there is no keyword replacement map. Undefined values and ambiguous constraints still require clarification.

Completed suggested code is retained exactly across transcript compression and many subsequent short follow-ups. History follows question order, so an older turn finishing late cannot replace a newer implementation. Suggestions are labeled as potentially mistaken, and later spoken corrections take precedence. The currently visible unfinished answer is also retained as an explicitly unfinished suggestion, so a follow-up can refer to the exact code already shown before completion. These memories are bounded and cleared when the meeting stops. When two older Codex streams occupy both slots, a third confirmed utterance cancels the oldest stream and waits for its actual cleanup before taking the slot; it cannot exceed the two-request bound.

## Evidence and resuming

Each answer and examiner review is checkpointed separately. A resume preserves reviewed rounds, requests only a missing review, and retries a failed answer. Usage-limit errors stop the suite immediately and retain pending cases.

```powershell
# Keep the same output directory, suite, models, efforts, round count and binary.
node scripts/adaptive-interview-suite.mjs --resume

# Read usage limits without performing an interview or purchasing credits.
src-tauri/target/debug/examples/adaptive-interview.exe --rate-limits

# Check that Luna grades current requirements separately from future probes.
src-tauri/target/debug/examples/adaptive-interview.exe --check-examiner
```

`COPILOT_INTERVIEW_CASES` selects comma-separated scenario names. `COPILOT_INTERVIEW_ROUNDS`, `COPILOT_INTERVIEW_MODEL`, `COPILOT_INTERVIEW_EFFORT`, `COPILOT_INTERVIEW_EXAMINER_MODEL`, and `COPILOT_INTERVIEW_EXAMINER_EFFORT` override settings. `COPILOT_INTERVIEW_SUITE` selects another suite, and `COPILOT_INTERVIEW_BINARY` selects a preserved executable. Changing the suite, settings, or executable SHA-256 requires a new output directory. Preserve an executable before rebuilding if its old run must remain resumable.

`suite.json` records configuration hashes, per-case completion, failures, pending cases, and latency summaries. Per-case JSON stores exact questions, answers, model reviews, output chunks with timestamps, and pipeline timing. Execution failures are excluded from answer latency samples and cannot pass a scenario. A scenario passes the text latency gate only when every requested round has a measured first sentence and its p95 is below 800 ms. The suite requires every round to be graded correct as well.

The first useful delta excludes internal intent framing. First-sentence measurement waits for a completed spoken sentence, excluding punctuation inside inline code, fenced code, and decimal numbers. Both timings are measured from submission of the confirmed text question. This benchmark excludes speech recognition, audio capture, native rendering, and overlapping interruptions. Its correctness grades are model judgments, requiring independent review; a Luna examiner is not independent proof of CUDA correctness. Native fixture checks cover scheduler and cleanup behavior but use a local HTTP service and do not prove signed-in Codex latency.

The 8,679,182-byte CPU model was downloaded at revision `f766f81d3cfdf7737ac64aad813d91bbfd56bf93` and verified against the publisher's SHA-256 `2bb026316b14a660486a75b1733cd3fbab8c2fd0314dc9af7be49f8cca967e4f`. Preprocessing uses the publisher's pinned numpy-only implementation; downloaded assets retain their license and source manifest in `.local/smart-turn-3.2`. No answer templates, new answer backend, or credential requirement were introduced.

The offline probe uses the actual production VAD code, sampled at 150, 300 and 510 ms of quiet, on twelve saved synthetic interviewer questions. The classifier sees only the audio prefix available at each candidate, retaining the most recent eight seconds. Each complete file is one interview question; every earlier quiet candidate is labeled continuation. Future audio determines these offline labels only. The model, source, waveform and VAD hashes are recorded. This is a whole-question boundary diagnostic, not natural human speech accuracy, held-out threshold selection, live ASR timing, or answer latency certification. Grammar-complete sentences inside a longer question can still be premature whole-question endpoints.
