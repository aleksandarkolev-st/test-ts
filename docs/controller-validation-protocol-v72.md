## Questions and capture

Native audio tests play unchanged, hashed mono PCM waveforms through **T24E390**. The app captures that output through its normal loopback path; local Nemotron transcribes it with 160 ms chunks. Typed tests invoke the native Ask control and explicitly exclude audio, transcription and automatic endpoint delay. The microphones are disabled in these synthetic recordings, rather than recording nearby people. Production continues to recognize both output and microphone sources.

These are simulated meetings and technical interviews with an authenticated assistant, not human interview certification. Saved questions include CUDA collective proofs, numerical reasoning, directed graphs with negative cycles, transactional invariants, changed constraints, and underspecified challenges. No expected answer or fixture identity selects production routing, acceptance, model, context retrieval or response policy.

All measured assistant runs use **`gpt-6.1-sol`, `low`**. The final contextual/backend/history/objective cells use standard tier (`null`); the original baseline/controller cells retain their source manifest's identical tier. The model catalog establishes availability, while recorded provider events establish actual inference; a failed startup does not prove inference capability or answer latency. Codex also validates the catalog's supported effort values. Unsupported direct-plan capabilities fail visibly; there is no billed API fallback.

## Reproduction

Build the acceptance application and preserve its binary hash before capture. The old baseline is a detached checkout at `c704a75`; do not copy new controller source into it. The six existing source-bound controller cases are specified in `artifacts/controller-v72/policy-playback/manifest.json`, including original waveform, context and journal hashes.

```powershell
node scripts/prepare-controller-validation.mjs artifacts/controller-v72/prepared
node scripts/prepare-controller-marathon.mjs artifacts/controller-v72/prepared/marathon-session.json
node scripts/controller-session-replay.mjs artifacts/controller-v72/plans/hour-final.json .local/controller-app artifacts/controller-v72/native/hour-final-codex codex
node scripts/run-controller-validation.mjs artifacts/controller-v72
node scripts/run-controller-plan-validation.mjs artifacts/controller-v72 .local/controller-plan-app
```

The sequential runner waits for the already-started interim Codex hour to finish, then runs final contextual and reasoning probes, behavior waveforms and a fresh elapsed hour on Codex before the corresponding direct ChatGPT-plan HTTP cells. It also runs a continuous three-hour Codex session, history controls, fresh application controls, brief/detailed controls, and interleaved baseline/controller pairs. It preserves failed runs and requires a new trial name for retries. It never merges a branch.

Ordinary acceptance mode intentionally disables saved plan credential loading. The explicit fifth replay argument `saved-plan`, supported by `3533bfa`, opts into normal saved credential loading and refresh persistence, with the normal authentication instance lock. Local HTTP fixtures cannot enable this mode. Use it only for the authorized authenticated comparison; there is no token copying or billed API fallback. The supplemental plan runner waits for the original queue to finish, first repeats short Codex tests on the same auth-enabled binary, then runs plan HTTP and interleaved paired history controls. Initial isolated-auth and expired/revoked-account failures remain recorded. Browser sign-in is required if the existing normal account is expired; a successful model catalog alone is not proof of successful inference.

The elapsed-hour plan uses actual wall-clock scheduling for 60 minutes, spoken source audio, typed exact-code probes, a decision recognized near the beginning and queried after 30 and approximately 57 minutes, a spoken follow-up triggered by visible output, and identical fixed-context questions at the start/end. A 3,600-turn virtual-clock Rust test is a separate fixture and cannot satisfy the elapsed-hour requirement.

The three-hour plan never restarts the application or session. It contains 113 turns, repeats identical source audio with the accumulating conversation, changes a code comparison operator and a separately scoped retention decision, and asks for original versus corrected versions after intervening technical discussions. At 90 and 174 minutes, exact collective-code recall and follow-up reasoning refer to the device function names actually generated in the first hour. Only those names enter the later question; the original code is not supplied as a hint. A missing earlier code fence is an explicit recall dependency failure. A probe at 180 actual elapsed minutes checks three-hour recall. Repeated source material is explicitly identified; this is a structured synthetic workload, not three hours of independently authored human speech.

HTTP local closure cannot prove remote cancellation. An unknown retirement holds local capacity for 1,500 ms, and unavailable local capacity fails after 2,500 ms. These are bounds on local resources and recovery, not a guarantee about the provider's outstanding computation. Codex uses actual terminal events or retires the owned connection on a bounded deadline.

History controls use finalized recognized speech from the v71 general hour up to native timestamps 0, 10, 30 and 60 minutes. Every cell appends exactly the same immediate exchange and target question. The resulting context bytes and waveform hashes are held constant across adapters. Fresh versus aged fixed-context cells isolate history length from application age; provider drift and observer overhead remain possible confounders. Interleaving reduces time confounding but does not remove it.

Production conversations remain RAM-only until Stop. The collectors explicitly write user-authorized validation artifacts; their persistence is not a production privacy-policy change. Never commit credentials, copied account databases, WebView profiles or raw secrets.

## Measurements and reasoning checks

`measure-controller-validation.mjs` requires an exact journal hash in its review file. Every row remains in correctness/completion/missing/error counts. Only a reviewed correct substantive claim actually painted in the viewport supplies useful-feedback latency. First words, input acknowledgements and ungraded openings are separate measurements. Missing or incorrect useful delivery ranks after finite correct delivery in the all-row p95, without assigning a fabricated timeout latency.

Codex actual submission is its instrumented flushed transport write. HTTP request-send timing does not prove a wire write; that field remains unknown. Capture uses physical device-position crossing bounds for the last nonzero source sample, host/native clock anchors, per-generation timings and actual overlay paint samples. Recognized question text can differ even with identical audio. Lexical WER is reported without silently repairing identifiers or normalizing numerals; source accuracy and accuracy conditional on recognition are separate judgments.

Native baseline/control captures check the frozen executable hash against its preserved build manifest and record source Git-blob hashes at that manifest's declared commit. Observed current checkout hashes are separately labeled: later edits must not be presented as the source of an older frozen executable. Renderer hashes remain independent, including the shared current renderer used with the c704a75 native baseline. Build provenance is not a reproducible-build attestation.

Reasoning review checks assumptions, causal arguments, counterexample executions, changed constraints, exact identifiers, synchronization contracts, arithmetic and completeness. It does not demand hidden chain-of-thought. Code and proof are assessed independently:

- `compile-controller-answer-cuda.mjs` uses the pinned real NVIDIA nvcc/MSVC toolchain from the existing compiler manifest to compile unchanged fenced CUDA/C++ sources. Failed snippets remain failures. Compilation does not prove GPU execution.
- `check-controller-answer-code.mjs` compiles/runs exact C++ code with explicit contracts. For nineteen-lane reductions, a documented CPU intrinsic shim and mechanical PTX lane-id substitution exercise the recorded algorithm's basis-vector coverage, all-caller results, matching collectives, participating sources and six-shuffle limit. This is CPU emulation, not NVIDIA hardware certification.
- Integer-branch checks bind original and corrected operators separately and execute 2,003 inputs per exact source. Log-recovery checks link the CRC-32C dependency explicitly requested by the question, compile the unchanged C++20 CLI, and supply independent valid/truncated/corrupted/sequence-gap/maximum-length byte files. No recovery algorithm is repaired.
- `check-controller-answer-python.py` evaluates unchanged required entry points against independent path/cycle enumeration, exhaustive small graphs, seeded multigraph/extreme-weight probes, and high-precision Decimal numerical oracles. These finite checks supplement the invariant and complexity proof review; they do not prove every allowed input.
- Exact-length walks use a separate forward dynamic-programming oracle, 6,448 small/large-length contracts, full small-witness continuity/cost checks and sampled indices at length 10^18. Predictable monitors use independent integer-product arithmetic and fully consume finite inputs, including invalid values after threshold crossing. Pipeline schedules are checked against resource, host/device ownership and timing inequalities plus an independent lower bound. Oracle regressions include deliberately invalid implementations; passing finite checks does not replace a proof.
- `check-controller-answer-sql.mjs` executes unchanged recorded SQL in an owned local PostgreSQL test instance. It schedules BEGIN/body/COMMIT separately to force two overlapping transactions, preserving surrounding comments and procedural bodies, checks serialization failures and a full retry, and shuts down only its own database. A separate control explicitly changes the actual isolation clause to repeatable read without rewriting comment text; that control is not scored as unchanged model source. Results bind the grader/parser source hashes. These synthetic database artifacts are separate from production meeting persistence. Run compilation/execution checks after capture or during documented scheduled quiet intervals, never during measured audio/inference.

The collector does not repair answers after generation. Reviewer verdicts, executable results and latency evidence are source-bound and remain separately labeled. Model-assisted review, if used, is not independent expert certification.

`prepare-controller-backend-controls.mjs JOURNAL REVIEW ORIGINAL_MANIFEST NEW_OUTPUT_DIRECTORY` derives identical backend inputs from actual accepted source contexts. It verifies journal/review/manifest/waveform hashes, carries the recorded objective/tier, includes incorrect reference outcomes, and discloses requests for which no accepted context exists. Exact-text replay uses actual recognized text; native replay keeps the original waveform and allows measured recognition differences. Neither mode recomputes context from each backend's new answers. The preparation tool is validation-only and has no production topic or intent policy.

`nemotron-finalization-replay.mjs JOURNAL NEW_OUTPUT VULKAN_DEVICE` tests the installed local runtime's documented commit protocol against automatic endpointing using source-bound short-utterance waveforms, preceding audio timing and controlled PCM chunk phases. It preserves 160 ms chunks, weights, device and endpoint settings, reverses trial order, and checks a later turn on the same socket. It uses an owned authenticated loopback service and writes opt-in synthetic test artifacts only. Direct PCM excludes WASAPI/resampling and assistant output load; the experiment does not establish the original native failure cause or authorize predicted words. Run it after native captures and before other heavy grading.

The corrected native collector explicitly samples the session archive before Stop and verifies every numeric archive counter clears afterward. Earlier captures retain their last pre-Stop row snapshot and an explicitly labeled post-Stop collection race; their journals are not rewritten. Expand and Answer-now probes use typed or injected finalized ASR events, new generation identities, exact frozen parent context and stale-control no-ops. Native waveform probes remain separate. Browser geometry/control checks run against the built bundle used by native replay; development-server navigation failures remain recorded rather than receiving larger timeouts.

Disclosed observer interference is attached to the source-bound row review. Measurements retain that row in all correctness, completion, missing-answer and overall latency results, report its interference flag, and provide a separate `nonFaultNonObserverAcceptedToWriteMs` distribution excluding requested fault probes and known observer interference. This filtered distribution alone does not certify a healthy warm connection. The marathon grading overrun is preserved in `docs/evidence/controller-marathon-interference-v72.json`.

## Promotion gates

The proposed targets remain acceptance criteria: healthy warm accepted-to-write p95 below 250 ms, ordinary follow-up useful feedback p50 at most 2 seconds/p95 at most 3 seconds, no silent lost final request, no obsolete active-panel text, no material correctness/completion regression, and no material age degradation under matched workload. Complex proofs have separate completion measurements. A successful fixture or one fast sample cannot establish these gates.

The final findings and recommendation must be based on completed authenticated captures and their audits. This protocol is not a latency-success claim or a substitute for implementation.
