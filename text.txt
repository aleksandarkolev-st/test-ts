uild it as a Windows-only local meeting copilot. Keep the MVP brutally focused:
Someone else asks a question → app detects it → ChatGPT generates an answer → answer streams into an overlay only you can see.

1. MVP scope
Must have
1. Windows 10/11.
2. Capture meeting/system audio.
3. Capture your microphone separately.
4. Live transcription.
5. Distinguish REMOTE speech from SELF speech.
6. Maintain rolling meeting context.
7. Detect questions from remote participants.
8. Generate an answer automatically.
9. Stream answer into an always-on-top overlay.
10. Overlay excluded from Windows screen capture.
11. Manual hotkey to ask something yourself.
12. Sign in with ChatGPT.
13. No cloud storage of transcripts.
14. One-click meeting start/stop.
Explicitly not MVP
No calendar integration, CRM, Slack, Gmail, team accounts, analytics, automatic speaking, macOS, meeting bots joining Zoom, recording library, post-meeting reports, speaker-name identification, or screen understanding.
Those are distractions until the core interaction works.

6. Audio capture
This is the first serious engineering problem.
Capture two independent streams.
Remote
Use WASAPI loopback capture.
This captures audio being rendered through the user's playback device.
Microsoft explicitly supports system loopback capture and also offers process-specific loopback capture on modern Windows. Microsoft Learn
Output:
AudioFrame {
    source: AudioSource::Remote,
    samples: Vec<f32>,
    timestamp_ms: 123456
}

User
Capture the selected microphone normally:
AudioFrame {
    source: AudioSource::Self_,
    samples: Vec<f32>,
    timestamp_ms: 123480
}

This distinction is extremely useful.
You immediately know:
REMOTE = somebody else
SELF   = user

You do not need speaker diarization for V1.

8. Local transcription
Use whisper.cpp.
It supports Windows, CPU execution, CUDA and Vulkan acceleration. GitHub
For the first version, use a smaller English model.
Your transcription interface:
pub struct TranscriptSegment {
    pub id: String,
    pub source: SpeakerSource,
    pub text: String,
    pub started_at: u64,
    pub ended_at: u64,
    pub is_final: bool,
}

pub enum SpeakerSource {
    Self_,
    Remote,
}

Example:
{
  "source": "remote",
  "text": "What are we expecting revenue to be next quarter?",
  "started_at": 59302,
  "ended_at": 62781,
  "is_final": true
}

Why local transcription
Because current ChatGPT-plan authorization documentation specifically describes eligible Responses API requests. It does not currently document realtime transcription sessions as part of plan sharing. OpenAI Developers
That gives you:
raw audio        stays local
transcription    local
AI answer        ChatGPT subscription

Good architecture.

10. Question detector
Do not trigger ChatGPT every time somebody speaks.
Create this state machine:
IDLE
 │
 ▼
REMOTE_SPEAKING
 │
 ▼
POSSIBLE_QUESTION
 │
 ▼
WAIT_FOR_END
 │
 ├──── new speech ───► REMOTE_SPEAKING
 │
 ▼
QUESTION_CONFIRMED
 │
 ▼
GENERATING

Question scoring:
+4 transcript ends in ?
+3 starts with why/what/how/who/when/where
+3 contains "can you"
+3 contains "could you"
+3 contains "do you"
+2 contains "what do you think"
+2 contains "any idea"
+2 rising intonation if available
-3 rhetorical pattern
-5 user is currently speaking

For V1:
score >= 4 → candidate question

Wait around:
400–600 ms

after remote speech stops.
Then generate.

16. Answer prompt
Use this as the initial instruction:
You are a private real-time meeting copilot.

Your job is to give the user an answer they can immediately say aloud.

RULES:

1. Answer the current question directly.
2. Maximum 3 short sentences.
3. Prefer information from the meeting context.
4. Use general knowledge only when meeting context does not contain the answer.
5. Never invent company-specific facts, dates, numbers or decisions.
6. If information is uncertain, clearly say so.
7. Do not introduce yourself.
8. Do not say "Based on the context".
9. Do not repeat the question.
10. Write natural spoken language.
11. Give the most useful answer first.
12. If the question is not actually answerable, say what information is missing.

Request input:
MEETING SUMMARY

...

RECENT CONVERSATION

REMOTE: ...
SELF: ...
REMOTE: ...

CURRENT QUESTION

"What date can we realistically launch?"

19. Screen-share invisibility
After the native overlay HWND is created:
SetWindowDisplayAffinity(
    hwnd,
    WDA_EXCLUDEFROMCAPTURE
)

WDA_EXCLUDEFROMCAPTURE tells Windows that the window should not appear in supported capture mechanisms. It exists specifically for cases such as recording controls that must remain local-only. Microsoft Learn
Rust concept:
use windows_sys::Win32::UI::WindowsAndMessaging::{
    SetWindowDisplayAffinity,
    WDA_EXCLUDEFROMCAPTURE,
};

unsafe {
    let ok = SetWindowDisplayAffinity(
        hwnd,
        WDA_EXCLUDEFROMCAPTURE,
    );

    if ok == 0 {
        // mark capture protection as failed
    }
}

The Rust Win32 bindings expose this API directly. Docs.rs
Important
Microsoft explicitly says this is not a DRM/security guarantee. Microsoft Learn
Therefore show:
● Share protection active

only after:
1. SetWindowDisplayAffinity succeeds.
2. GetWindowDisplayAffinity confirms it.
Otherwise:
⚠ Share protection unavailable

Never lie to the user.

26. Main loop
Conceptually:
while meeting_active {

    let event = event_bus.next().await;

    match event {

        TranscriptFinal(segment) => {

            context.push(segment.clone());

            if segment.source == Remote {

                if question_detector.is_candidate(&segment) {

                    question_detector.wait_for_completion().await;

                    let question =
                        question_detector.build_question();

                    generation.cancel_existing();

                    let prompt =
                        context.build_prompt(question);

                    generation.stream(prompt).await;
                }
            }
        }

        RemoteSpeechStarted => {
            if generation.is_active() {
                generation.cancel();
            }
        }

        _ => {}
    }
}

That is essentially your product.
